# S-003 分级阅读器

状态：**done**（12/12 验收通过）　依赖：S-001（足量词族，否则生词率必然超阈）

## 背景 / 问题

阶段 1 的另一半是"阅读量"。科学依据：生词率落在 **2%–5%** 才能兼顾可理解输入与附带习得，
**高于 5% 的文本不应进入初级批次**。目前应用只有单词卡，没有阅读通道。

## 目标

1. 短文阅读：按用户已知词族**实时计算生词率**，超出区间给出警告
2. 生词着色，点词查看释义 / 一键加入学习
3. 支持窄读：同一主题连续多篇

## 计算规则

```
unknownRate = 未知词元数 / 总词元数
```

- 以**词族**为判定单位（用户已知词族集合来自 `knownFamilies`）
- 词元切分：小写化，保留 `'` 与 `-`，其余标点转空格
- 判定区间（`lib/coverage.ts` 的 `COMPREHENSIBLE_RANGE`）：`[0.02, 0.05]`

## 实现要点

1. 读物存在共享库 `elm-shared.passages` / `sentences`，字段含 `cefr / topic / tokenCount`
2. 阅读页 `/reading`：
   - 列表按 `cefr` + `topic` 分组（窄读）
   - 正文渲染时逐词着色：已知=常规色，未知=高亮
   - 顶部显示：生词数、生词率、是否在可理解区间
3. 点未知词 → 侧栏显示释义（走 S-002 的 `ensureDefinition`）+「加入今日学习」
   - 加入学习 = 在用户库写入该卡的初始 `reviewStates`（**只影响该用户**）
4. 读物导入：与 S-001 同构，走文本导入通道

## 验收标准

1. 打开一篇含 5% 以上生词的文本时，界面明确提示"生词率过高，建议先补充 K2 词汇"
2. 生词率计算与手工统计一致（允许 ±0.5% 的切分差异）
3. 已知词族的词不着色，未知词族着色
4. 「加入今日学习」后，该用户的今日队列数量增加，其他用户不受影响
5. `tsc --noEmit` / `next build` 通过，控制台零错误

### 关键实现决策

1. **生词率以词族为单位**，未知词按词形去重后统计；显示值取「未知词元 / 总词元」
2. **轻量后缀还原**（s/es/ies/ed/ing/ly/er/est）作为近似词形还原。
   词族表只登记原形，若不还原会把 `comes`、`waiting` 误判为生词。
   这是**近似**，非完整词形还原，已在代码中注明。
3. **「加入今日学习」** = 写入初始 `ReviewState` 并把 `dueAt` 设为当前时间，
   使该卡立即进入队列（只写当前用户的库）。
4. 读物播种与词库播种**分开判断**（`ensurePassagesSeeded`），
   避免"已导入词表的老库因为词族非空而永远拿不到读物"。

### 顺带修复的内容缺陷

**`a` 与 `i` 不在词表中**。`scripts/fetch-wordlist.mjs` 用 `word.length < 2` 过滤，
把英语最高频的两个词删掉了，导致阅读中它们被标为生词。
已改为保留单字母词 `a` / `i`；重新生成词表并导入后词族数 3002 → 3004。

### 测试脚本自身的缺陷（已修）

1. 用 `parseFloat("生词率 100.0%")` 取值 → NaN，应使用 `/([\d.]+)%/` 提取
2. 清理步骤把 `elm.activeUser` 写成裸字符串（丢引号），导致后续 `JSON.parse` 抛错，
   且该损坏会**连带打挂所有验收脚本**。已改为 `JSON.stringify`，
   并给四个脚本加上容错取值（裸字符串也能解析）
3. `verify-s002` 用 `startsWith(lemma)` 挑选词条 → 目标为 `a` 时会选中 `about`。
   已改为按词条名**精确匹配**（读取 `.font-medium` 文本）

### 交叉发现（导致 s002 假失败的真因）

`verify-legacy-word` 曾用 `about<TAB>1` 导入，把 `about` 的 `freqRank` 从 36 覆盖为 1，
使之排到 `the` 之前，进而让 `verify-s002` 里"按频率取第一个待生成词"的逻辑选中 `about`（已 ready）→
6 项断言失败。**这不是 S-003 的缺陷，而是测试之间通过共享数据互相污染**。

修复：`verify-legacy-word` 改为读取并沿用该词族当前的 `freqRank`，并新增一条断言
"词频排名未被测试本身打乱"；随后整体重导入词表恢复被污染的排名。
