# S-009 内置离线释义（不依赖大模型即可开箱出题）

状态：**done**（5/5 验收通过）　依赖：D2 D7 D12、S-001

## 背景：这是"能不能部署上线"的真正阻断项

S-008 交付后首页「实际保持率」显示 **6%~7%**（目标 90%）。这个数字是真实的诊断信号：
共享词库 3002 词里**只有 93 个有释义**，而 D12 要求「必须在页面上作答、系统客观判定」——
释义未生成的卡根本进不了队列。于是新用户导入词表后，学习页几乎开不了题。

原先的解法是「配个大模型 key，去设置页批量生成释义」（S-002）。但：
- 要求每个用户自备 key，且要看懂 base_url / 模型名怎么填
- 转发代理 `proxy/server.mjs` 只能跑在本机，部署到公网后对访问者无效
- 直连第三方端点会被 CORS 拦

**结论：让学习者先解决 API 配置才能开始背单词，这个门槛不可接受。**

## 决策

| 编号 | 决策 | 理由 / 边界 |
| --- | --- | --- |
| D16 | 释义**优先由开源词典在构建期生成并内置**（ECDICT），大模型只作为可选的"更贴合学习场景"的增强；内置数据随产物发布 | 零配置即可学习；构建期一次性处理，运行期零请求、零成本、零 CORS 问题 |

## 实现

### 1. 构建期数据生成：`scripts/build-definitions.mjs`

- 数据源：**ECDICT**（`skywind3000/ECDICT`，76 万词条）的 `ecdict.csv`（62.9 MB，缓存在系统临时目录）
- 用**引号状态机**解析 CSV（字段内可能含逗号与换行，不能按行 split）
- 按词表筛出需要的词，产出 `public/wordlists/definitions-zh.json`（0.51 MB）

实测：

```
目标词表 3000 词 → 命中 2996（99.9%）
含中文释义 2996 · 含考纲标签 2096
未命中 4 个（sitemap / pubmed / tripadvisor / permalink，均为词表噪声）
```

### 2. 应用侧导入：`lib/data/definition-importer.ts` + 设置页

- 读取内置 JSON → 补写 `words`（`definitionEn` / `definitionL1` / `ipa` / `definitionStatus`）、
  `senses`、`cards` 的正反面文案
- **幂等规则**：已有释义且**不是**词典来源（即大模型生成或手写）→ 跳过；
  词典来源的允许刷新（否则修好词典数据后只能让用户清库重建）
- 补写 `senses` 时保留原有例句关联与词序，只更新释义文本
- 只写共享库（D2），不触碰任何用户进度

### 3. 数据文件纳入版本管理

`public/wordlists/*` 原本被整体忽略，但这两个文件是**部署产物必需**的
（否则 clone 后构建出的应用里没有词表和释义），已在 `.gitignore` 中显式放行。

### 过程中修掉的两个数据质量问题

1. **释义行粘连**：ECDICT 的多释义分隔用的是**字面 `\n`**（反斜杠 + n 两个字符），
   不是真换行。直接按 `\n` 切分会得到 `prep. 在...周围, 大约, 有关, 关于\nadv. 大约, 四处...`，
   卡片上会显示成一长串。已在清洗时先还原成换行再按行截取。
2. **词典数据无法刷新**：初版「已有 `ready` 释义一律跳过」导致修好词典后无法重新导入。
   改为按来源区分（见上文幂等规则）。

## 已知限制 / 风险

- **许可是最需要注意的一点**：ECDICT 仓库为 **MIT**，但其数据是多方来源汇编
  （自建词表 + 开源字典 cdict + BNC 语料库 + WordNet + 网友贡献）。
  **个人本地学习使用无碍；若要商业分发，请自行复核各来源授权。**
  生成的数据里已写入 `source` / `sourceUrl` / `license` 字段以便追溯。
- **英文释义质量参差**：ECDICT 的 `definition` 主要来自 WordNet，含 `s.` / `r.` 等词性缩写，
  个别词条还会出现明显不合适的释义（如 `the` → "v. i. See Thee."）。
  而卡片背面优先显示英文（`backText` 的既有设计），因此这部分体验会打折。
  缓解方向：对词典来源的词允许大模型覆盖（当前策略是**不覆盖**大模型成果，反向需要额外开关）。
- **只有 3000 词**：数据按内置词表生成。用户若导入更长的词表，超出的词仍需大模型补全。
- 音标覆盖 2414/3002（约 80%），其余为空。
