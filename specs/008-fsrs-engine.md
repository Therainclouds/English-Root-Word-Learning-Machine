# S-008 排程引擎升级为 FSRS-6

状态：**done**（离线 15/15 + 运行时 16/16 + 专项 6/6）　依赖：D4 D9 D12、S-001

方法论依据：`docs/learning-science.md`

## 背景：为什么换掉 SM-2

原实现是 SM-2（1987）的变体：`ease × 固定乘数` + 硬编码前 5 次间隔 `[1, 3, 7, 16, 35]`。
在那个年代这是合理选择——**没有数据**可用。而现在（2026）公开的间隔重复数据集已达
**17 亿条真实复习记录**（`FSRS-Anki-20k`），FSRS-6 的 21 个默认参数就是在这些数据上训练出来的。

官方基准（`srs-benchmark`，3.499 亿条评测，同一测试集）：

| 算法 | 参数量 | Log Loss ↓ |
| --- | --- | --- |
| RWKV-Instant | 2,762,884 | 0.2773 |
| **FSRS-7 recency** | 34 | 0.3363 |
| **MOVING-AVG**（零参数） | 0 | 0.3369 |
| **FSRS-6（个人优化后）** | 21 | **0.3460** |
| FSRS-5 | 19 | 0.3561 |
| **FSRS-7 默认参数（不做个人优化）** | 0 | **0.3620** |
| AVG（常数基线） | 0 | 0.3945 |
| ACT-R | 5 | 0.4033 |
| HLR（Duolingo） | 3 | 0.4694 |

三个结论决定了本次范围：

1. **默认参数（＝群体先验）已拿到绝大部分收益**：个人优化只从 0.3620 改善到 0.3460（约 4.4%）。
   因此"用户还没攒够 1000 条记录，所以先别换"这个理由不成立——直接用官方默认参数即可。
2. **不需要自己训练模型**：`ts-fsrs`（MIT，纯 TS，FSRS-6）直接可用。
3. **零参数的"移动平均"几乎追平 SOTA**（0.3369 vs 0.3363）→ 说明"个体基准水平"比算法结构更决定预测能力，
   这直接催生了本 spec 的第二个交付物：**「我的真实保持率」面板**。

## 决策

| 编号 | 决策 | 理由 / 边界 |
| --- | --- | --- |
| D14 | 排程引擎改用 **FSRS-6**（`ts-fsrs`，MIT），参数用官方默认值；**不做个人参数优化**（待复习记录足够后再评估） | 默认参数在 17 亿条记录上训练，已覆盖绝大部分收益；自建优化器需要 ≥1000 条记录且成本不对等 |
| D15 | 掌握判定口径由"0–1 启发式"改为 **FSRS 稳定度天数**（`minStabilityDays`，默认 21 天 ≈ "能记三周"） | `stability` 在 FSRS 中本就是"R 衰减到 90% 所需天数"，用它判定比自造指标更有物理意义；实测连续答对 2 次 S≈13.8、3 次 S≈57 天，故 21 天与旧口径（0–1 的 0.8 + reps ≥ 3）强度相当 |

## 实现要点

1. **引擎替换点只有一处**：`lib/srs.ts` 的 `schedule()`。`buildSession`（组卷/限额/交错）、
   学习页、卡片结构全部不动。
2. **参数配置**（`FSRS_BASE_PARAMS`）：
   - `request_retention` ← 设置页的「目标保持率」（**此前是摆设**：滑块能拖、类型与默认值都有，排程代码从未读过它）
   - `enable_fuzz: true`：给长间隔加抖动，避免同批导入的卡永远同一天到期
   - `maximum_interval: 365`：一年封顶。实测默认参数下"连续答对 5 次"会排到 586 天后，对语言学习不现实
   - `enable_short_term: false`：**不**启用分钟级学习步骤，理由见"已知限制"
3. **客观判定只有两档**（D12）：答错 → `Rating.Again`，答对 → `Rating.Good`；Hard / Easy 不产生。
4. **旧数据迁移**：SM-2 时代的 `stability` 是 0–1 的启发式，直接喂给 FSRS 会被当成"不到 1 天"。
   迁移规则：`reps > 0 && stability ≤ 1` 时，用 `intervalDays` 重新估计 S
   （FSRS 保证 `I(0.9) = S`，所以"上次被安排的间隔"就是最合理的估计）。
   迁移在**读取时**发生，不改写历史记录。
5. **日志补特征**：`ReviewLog` 增加 `elapsedDays` 与 `stateBefore`——这是将来训练个人参数的必需特征，
   **且无法事后回填**，所以现在就开始记。
6. **「我的真实保持率」面板**：`retentionOf(logs)` 取最近 100 次的答对比例，首页与目标保持率并排显示。
   依据是第 3 条结论：零参数的个体基准几乎追平 SOTA。

## 数据模型变更

`ReviewState`（用户库，无需升 `DB_VERSION`——只是文档内加字段）：

| 字段 | 变化 | 说明 |
| --- | --- | --- |
| `stability` | **语义变更** | 0–1 启发式 → FSRS 稳定度（**天**） |
| `difficulty` | 新增 | FSRS 难度 [1, 10] |
| `fsrsState` | 新增 | 0=New 1=Learning 2=Review 3=Relearning |
| `learningSteps` | 新增 | 学习步骤下标（未启用分钟级步骤时恒为 0） |
| `elapsedDays` | 新增 | 本次复习距上次的天数 |
| `ease` | **删除** | FSRS 不需要；仅旧记录里残留该字段，读取时忽略 |

`ReviewLog`：新增 `elapsedDays?`、`stateBefore?`。

`PathNode.masteryRule`：`minStability` → **`minStabilityDays`**（词汇节点 0.85 → 21 天，阅读/输出节点 0.8 → 14 天）。

## 已知限制 / 风险

- **评分档位与公开数据不匹配**：Anki 数据是自评 4 档（again/hard/good/easy），我们只有客观 2 档，
  因此 FSRS 的 Hard 专用参数（`w15`）与 Easy 专用参数（`w16`）在我们的场景永远不触发。
  这也是**不做个人参数优化**的原因之一——按两档数据去拟合会得到一个与公开基准不可比的模型。
- **未启用分钟级学习步骤**（`enable_short_term: false`）：学习页按 `index` 顺序消费队列，
  分钟级到期卡会让队列在会话中途重排，导致跳卡。要启用必须先把它改成"按 cardId 定位当前卡"。
  代价是首次接触缺少分钟级巩固——官方基准显示同日复习恰是所有算法的软肋（FSRS-6 含同日场景 log loss 从 0.3460 升到 0.3842）。
- **个体化参数尚未优化**：需要 ≥1000 条复习记录；`elapsedDays` / `stateBefore` 已开始记录，
  将来可用 `@open-spaced-repetition/binding`（Rust + WASM）在浏览器内训练。
- **掌握门槛重新校准**：`minStabilityDays: 21` 是按"旧口径 0.8 + reps ≥ 3"的强度反推的，
  尚无真实用户的长期数据支撑，可能需要按实际解锁速率微调。
- **实际保持率面板样本 < 20 次时只是参考**（`retentionOf` 返回 `enough: false`）。
  实测已观察到面板显示 7%——它真实反映了"释义未就绪时用户在瞎猜"，是有用的诊断信号。
- 开源复习数据集（`anki-revlogs-10k`）**需登录并同意自定义条款**、且**不含牌组名称**，
  因此"按英语词汇类牌组分群训练参数"这条路目前走不通。
